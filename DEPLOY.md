# Deploying device-provisioning (Python)

Generated by BOT's Deploy stage. Everything below runs from the folder that contains this file.

## 1. Build and test locally

    pip install -r requirements.txt
    python -m pytest -q

Or run the whole chain with `scripts/build.sh` (Linux/macOS) or `scripts/build.ps1` (Windows).

## 2. Build the Docker image

    docker build -t device-provisioning:latest .
    docker run --rm -p 8091:8091 device-provisioning:latest

The Dockerfile is multi-stage: the first stage builds the code and runs the unit tests, so a broken build never produces an image.

## 3. Run with Docker Compose

    docker compose up --build

## 4. CI/CD with GitHub Actions

Commit the project with `.github/workflows/ci-cd.yml`. On every push and pull request it builds, runs the unit tests and builds the Docker image. On `main` it also pushes the image to the GitHub Container Registry (`ghcr.io/<owner>/device-provisioning`).

The optional `deploy` job runs only when the repository variable `DEPLOY_ENABLED` is `true` and the secret `KUBE_CONFIG` holds a base64-encoded kubeconfig.

## 5. Kubernetes

    kubectl apply -f k8s/
    kubectl rollout status deployment/device-provisioning
    kubectl port-forward service/device-provisioning 8080:80

Edit the `image:` line in `k8s/deployment.yaml` to point at your registry first.
